## 演習

### 1. 回答の違い（素のLLM vs エージェント）

* **素のLLM (`app.ask`)**: 講座情報を保持していないため、「〜の可能性が高い」と前置きした上で一般論（レベル1〜3）を推測で回答し、「講師に確認を」と締めくくった。
* **エージェント(`app.agent`)**: `search_glossary` で用語集を検索し、定義（`homework-levels`）に基づいた正確な仕様（3段階・どれか1つで完了・原則採点なし・第1回参照）を回答した。

### 2. `--trace` によるツール呼び出し

* **「LoRAとQLoRAの違いは？」**:
* `search_glossary({'query': 'LoRA'})`
* `search_glossary({'query': 'QLoRA'})`
* ※docstring の指示通り、1単語ずつ計2回検索。


* **「第2回の内容から確認問題を1問出して」**:
* `make_quiz({'lecture': 2})`（計1回）



### 3. LLM呼び出し回数 (`requests`)

* **回数**: いずれの質問も **2回**
* **LoRA/QLoRA**: `requests=2`, `tool_calls=2`
* **確認問題**: `requests=2`, `tool_calls=1`


* **内訳**: 1回目でツール呼び出しを決定し、2回目でツールの実行結果をもとに最終回答を生成。

### 4. 追加したツールと docstring

* **関数**: `make_quiz(lecture: int) -> str`
* **処理**: 指定された回の用語を用語集から `random.choice` で1つ選び、`{"question": "「○○」の意味は？", "answer": 定義}` の JSON 文字列を返す。
* **docstring**:
> 指定した回（1始まりの整数）の用語集から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』『復習クイズを出して』のように、ある回の内容について問題を出してほしいと頼まれたときに使う。返り値の answer は出題後に答え合わせで使う。


* **動作確認**: `--list-tools` への表示を確認、`pytest` 11 passed。

## 宿題

* **取り組んだレベル**: 実装
* **概要**: 学習記録を `learning_log/` に保存するツール `save_learning_log` を作成。不可逆な操作のため、Pydantic AI の `requires_approval=True` を用いて実行前のユーザー承認フローを導入した。

### 実装と検証結果

1. **ツール実装 (`app/tools.py`)**:
* `save_learning_log(title, content)` を実装。
* `learning_log/{日時}_{題名}.md` として Markdown 形式で保存（記号置換、パストラバーサル防止対策済み）。


2. **エージェント設定 (`app/agent.py`)**:
* `requires_approval=True` を付与して登録。
* `output_type=[str, DeferredToolRequests]` を指定。


3. **CLI での承認制御**:
* `result.output` が `DeferredToolRequests` の間、題名と本文を提示して `実行してよいですか？ [y/N]` を確認。
* **承認 (y)**: `True` を `DeferredToolResults` に渡し、`message_history` を引き継いで `run_sync` を再実行。ファイルが生成され、モデルが「保存しました」と回答。
* **拒否 (n)**: `ToolDenied` を渡して再実行。ツールから「利用者が保存を許可しませんでした」が返り、モデルが「保存が見送られました」と回答。


4. **テスト**:
* `pytest` 11 passed（`TestModel` では承認待ちで停止するため、実ファイルは生成されずテストが通過）。



### 気づき

* **docstring による振る舞いの制御**:
* 当初「保存の前に利用者の承認が必要」と書いたところ、モデルが会話上で「保存しますか？」と聞き返してしまい、ツールが呼ばれなくなった（二重承認の発生）。
* 「確認はツール呼び出し後にシステムが行うため、呼ぶ前に文章で確認しなくてよい」と修正したことで、ツール呼び出しから CLI の承認フローへ正常に進むようになった。
* **学び**: docstring は人間向けの単なる説明ではなく、**モデルの自律的な挙動を決定づける指示（プロンプト）である** ことを実感した。



### 疑問・今後の課題

* **トークン使用量 (`usage`) の計測**:
* `--trace` の `[usage]` には承認後の再実行分（requests=1）しか反映されない。承認フロー全体の正確なコストを把握するには、前後の run の usage を合算する仕組みが必要。


* **引数の上書き**:
* 承認時に本文を手直しして保存できるよう、`ToolApproved(override_args=...)` を用いた引数書き換えを試したい。
